# libSceSsl technical debt

### Unknown function info

- [sceSslCreateConnection, sceSslDeleteConnection, sceSslConnect, sceSslRead, sceSslWrite, sceSslClose](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - imported by `ffmpeg.prx`; signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs): `int (int conn)` for `sceSslConnect` and `sceSslClose`, `int (int conn, void* buf, size_t len, int flags)` for `sceSslRead` and `sceSslWrite`. The connection is a Mbed TLS 3.6 TLS client over the libSceNet socket given to `sceSslCreateConnection` (`sceNetSend` and `sceNetRecv`); the socket stays open after `sceSslClose` and `sceSslDeleteConnection`. Only TLS 1.2 is negotiated (`MBEDTLS_SSL_PROTO_TLS1_3` is off), as SharpProspero's `SceSslVersion` ends at TLS 1.2; the console's maximum version is not known. The server is always verified: its chain must end at a CA loaded with `sceSslLoadCert` or at a root of the host (Windows `ROOT` store, or the first CA bundle found under `/etc`), and its name must match the host given to `sceSslCreateConnection`, which is also sent as SNI; the console's own root list is not available, so trust follows the host. Handshake, verification and socket failures throw with the Mbed TLS or libSceNet error instead of returning, because the console's error codes are unknown; so do a non-blocking socket, nonzero `flags`, a read, write or close before the handshake or after `sceSslClose`, a second `sceSslConnect` and an empty host. `sceSslRead` returns 0 on a close notification or end of stream and `sceSslWrite` returns the bytes Mbed TLS took, which can be fewer than `len`. A connection holds one lock, so a read blocked on one thread delays a write on the same connection from another. Records are allocated from the context's pool, so a small pool throws `bad_alloc` during the handshake; the trust anchors are parsed outside the pool. Unknown context returns `SSL_ERROR_INVALID_ID` (0x8095F006) from `sceSslCreateConnection`; an unknown connection, a terminated context and a null host throw

- [sceSslGetSubjectName, sceSslGetIssuerName, sceSslGetNameEntryCount, sceSslGetNameEntryInfo, sceSslFreeSslCertName](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs). The certificate is a handle from `sceSslGetCaList`; a name handle belongs to the context until `sceSslFreeSslCertName` and keeps its certificate alive after `sceSslUnloadCert`. Each attribute of a multi-valued RDN counts as one entry, in certificate order. `oidname` receives the dotted numeric OID ("2.5.4.3") with a terminating null, which is one reading of SharpProspero's "its OID as text"; the console may write a short name such as "CN". `value` receives the raw attribute bytes without a terminator and `valueLen` their count. An unknown context, certificate or name, an entry out of range, null outputs and buffers too small throw, since the console's error codes are unknown
- [sceSslLoadCert, sceSslGetCaList, sceSslFreeCaList, sceSslGetCaCerts, sceSslFreeCaCerts, sceSslUnloadCert](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - signatures and layouts follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs). PPSA15508/01.002.000 calls `sceSslLoadCert` with one 1,408-byte PEM CA and null client certificate/key arguments; this confirms that call shape, not console error behavior. Mbed TLS 3.6.7 parses DER/PEM chains and checks an optional client certificate/key pair. Imports are retained per context and committed together; a failed import preserves existing credentials. CA queries return independently owned snapshots; unload clears active credentials while outstanding snapshots remain valid. Appending repeated CA imports, snapshot lifetime across unload, memory overhead and error precedence have not been measured on a PS5. Invalid loads, malformed material, exhausted pools and unsupported keys throw rather than inventing console error codes. No root bundle is shipped; an empty context still returns `NOT_FOUND`. The existing null-list error, unknown-context behavior and legacy clearing of foreign raw CA lists remain unchanged. Certificate readers remain unimplemented. Loading credentials neither starts a TLS connection nor authenticates a peer
